# Internationalization (i18n)

The portfolio supports English and Portuguese. This document explains how the i18n system works and how to add or update translations.

---

## Overview

Custom lightweight i18n — no third-party library. Implemented as a React Context (`LanguageContext`) with a type-safe translation function.

**Languages:** `en` (English), `pt` (Portuguese)
**Persistence:** `localStorage` key `"language"`
**Default:** Detected from browser language (`navigator.language`)

---

## How It Works

```
LanguageContext stores: language + setLanguage + t()
          ↓
t("intro.greeting") → looks up key in current locale → returns string
```

### Translation Function Signature

```ts
t(key: DotPath<LocaleShape>): string
t(key: DotPath<LocaleShape>, params: Record<string, string>): string
```

- `key` is compile-time checked — TypeScript will error if the key doesn't exist
- `params` for interpolation: `t("copyEmail.copyAria", { email: "x@y.com" })` → replaces `{email}` in the string

---

## Using Translations in Components

```tsx
import { useLanguage } from "../context/LanguageContext"

function MyComponent() {
  const { t, language } = useLanguage()

  return (
    <div>
      <h1>{t("intro.greeting")}</h1>
      <p>{t("intro.bio")}</p>
    </div>
  )
}
```

### Changing Language

```tsx
const { setLanguage } = useLanguage()

<button onClick={() => setLanguage("pt")}>Português</button>
<button onClick={() => setLanguage("en")}>English</button>
```

## Locale Files

Located at `src/locales/en.ts` and `src/locales/pt.ts`.

Structure: **flat object with dot-notation-style keys** (not nested — the keys themselves contain the dots as naming convention, but the actual object is flat at each level using nested objects).

Example structure:
```ts
// src/locales/en.ts
export const en = {
  intro: {
    greeting: "Hi, I'm Maycon",
    bio: "Product Designer ...",
  },
  home: {
    projects: "Projects",
    experience: "Experience",
  },
  copyEmail: {
    copyAria: "Copy {email} to clipboard",
    copied: "Copied!",
  },
  // ...
} as const
```

The `as const` assertion is critical — it enables the `DotPath` type to generate a union of all valid key paths at compile time.

---

## Adding a New Translation Key

1. Add the key to `src/locales/en.ts`:
   ```ts
   newSection: {
     newKey: "English text",
   }
   ```

2. Add the same key to `src/locales/pt.ts`:
   ```ts
   newSection: {
     newKey: "Texto em português",
   }
   ```

3. Use it in a component:
   ```tsx
   t("newSection.newKey")
   ```

TypeScript will error at step 3 if the key doesn't exist in both locale files.

## Localized Content (Data Layer)

Project and case study content is also localized, but through a different mechanism — factory functions that take `language` as a parameter.

### Projects
```ts
// src/data/projects.ts
getProjects(language: Language): Project[]
```

The `projectsCatalog` stores `LocalizedText` per field, and `getProjects` selects the right variant.

### Experience
```ts
// src/data/experience.ts
getExperience(language: Language): Experience[]
```

### Case Studies
```ts
// src/data/case-studies/index.ts
getCaseStudy(slug: string, language: Language): CaseStudyData | undefined
```

Each case study file exports a function `(language: Language) => CaseStudyData`.

## `LocalizedText` Type

Used for fields that need to be different per language:

```ts
type LocalizedText = Record<Language, string>

// Usage in data files:
const title: LocalizedText = {
  en: "English title",
  pt: "Título em português",
}
```

---

## Language Type

```ts
type Language = "en" | "pt"
```

---

## DotPath Type

The `DotPath<T>` utility type recursively generates a union of all valid dot-notation paths in a type `T`. This gives `t()` compile-time key validation:

```ts
// If en.ts has { intro: { greeting: string } }
// DotPath<typeof en> includes "intro.greeting"
// TypeScript errors if you write t("intro.greting") (typo)
```

---

## Interpolation

For dynamic strings with placeholders:

Locale file:
```ts
copyAria: "Copy {email} to clipboard"
```

Component:
```tsx
t("copyEmail.copyAria", { email: "hello@example.com" })
// → "Copy hello@example.com to clipboard"
```

Placeholders use `{name}` syntax. Multiple params are supported.

---

## Adding a New Language

Currently out of scope, but the system is built to support it:
1. Add the new language to the `Language` union type
2. Create `src/locales/xx.ts` with all keys
3. Update `LanguageContext` to handle the new language
4. Update `LanguageSelector` to show the new option
5. Update all `LocalizedText` objects in data files
